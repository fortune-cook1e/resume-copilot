# Resume Copilot 产品定义

状态：首版产品方向已确认；具体技术方案、Delivery Slices 与完整验收范围待设计。本文描述目标，不代表相关能力已经实现。旧 Web 仅供参考，不能据此扩展新版范围。

## 1. 产品定位

帮助求职者管理真实经历，并针对不同岗位创建、编辑和导出独立简历。平台本身是可用的简历工作台；Codex 是可选的协作入口。用户不需要购买 OpenAI API Key 才能使用平台，也不必连接 Codex 才能手动创建简历。

首版不在平台内构建 Agent 或聊天界面。用户在 Codex 客户端对话；平台通过经用户授权的连接提供数据、接收草稿或修改建议。**内建 Agent 仍是后续产品方向，优先级低于手动闭环和 Codex 协作闭环**；届时再设计其能力、交互与实施阶段，不把旧版 Agent 方案自动当成首版需求。

## 2. 数据与内容边界

- **个人经历库**：用户在平台手动维护并确认的可复用真实事实，包括教育、工作、项目及成果等。不要求一次填完。Codex 首版只读已确认事实，不能直接新增或更正经历库内容。
- **简历**：按基本信息、教育、工作、项目等结构化内容保存的独立草稿或成品；用户通过表单编辑、预览并导出 PDF。首版提供一个可靠模板，必要时支持自定义分区；不预设高级排版功能。
- **目标岗位**：用户可在 Codex 对话中说明岗位方向或粘贴 JD 文本，用于当次协作。平台首版不单独存储岗位方向、JD 或 Codex 聊天记录，也不自动读取职位链接。
- 经历库是事实来源，简历是针对目标选取并表达的独立内容。修改简历不会自动更新经历库；经历库变化也不会自动修改已生成的简历。新简历不以其他简历作为自动参考来源。

## 3. 首版用户体验

### 手动闭环

用户无需连接 Codex，即可建立和编辑经历库；可从空白简历开始，在结构化表单中填写、编辑、预览，并导出 PDF。应用内提供简历列表。简历不会因为经历库的后续变更而自动改写。

### Codex 协作闭环

1. 用户在平台登录，并独立授权 Codex 连接自己的数据；Codex 账号与平台账号不能靠邮箱相同自动关联。首版以远程 MCP 连接为目标；未来可将相同能力包装为更易安装的 plugin，但不依赖公开上架完成首版。
2. Codex 通过 MCP 工具交换结构化数据，而不是点击网页或填写表单。创建简历时可读取用户已确认的经历；修改已有简历时，仅在用户明确指定后读取该份简历，不默认读取其他简历。
3. 用户在 Codex 中给出岗位方向或粘贴 JD。Codex 可基于已确认事实创建独立、可编辑的简历草稿；无需逐条批准新草稿措辞，但不得把 JD 要求或未知信息写成用户已具备的经历、技能或数字。缺少事实时应询问，而不是编造。
4. 修改已有简历时，Codex 提交待确认建议；平台显示修改前后内容，用户接受或拒绝。拒绝不改变原简历。若简历在建议产生后被手动修改，旧建议不能应用，须基于最新版重新提出；首版不自动合并冲突。
5. 平台校验、保存与展示简历数据，由用户在平台手动编辑、预览和导出。MCP 的工具粒度、JSON 格式、授权范围及失效策略留给技术方案，不把 Codex 的工具调用等同于用户已确认修改。

## 4. 首版范围与后续方向

**首版闭环**：手动维护已确认经历；独立创建和管理简历；表单编辑、预览与 PDF 导出；通过用户授权的 Codex/MCP 读取经历、创建草稿及提交已有简历的待确认修改。优先把这些能力拆成可独立验证的 Delivery Slices，不要求一次完成。

**首版不做**：平台内建 Agent/chat、Codex 向经历库写入事实、自动提取旧简历文件中的经历、职位链接抓取、保存 JD 或 Codex 对话、自动参考其他简历、复杂模板库或自动合并过期建议。

**后续方向**：内建 Agent 协作仍要开发，但排在首版闭环之后；对话访谈、事实提取与确认等具体能力届时设计。职位链接、简历文件导入、Codex plugin 分发及更丰富的排版能力按需要另行设计和排序。这些不是已授权的实施任务。

## 5. 典型用户旅程

- **完全手动**：登录平台 → 手动填写或维护经历 → 创建空白简历 → 编辑、预览 → 导出 PDF；不依赖 Codex。
- **用 Codex 创建**：手动确认经历 → 授权连接 → 在 Codex 中提供岗位方向或 JD → Codex 读取已确认经历并提交独立草稿 → 用户回平台检查、编辑、预览和导出。
- **用 Codex 修改**：用户指定一份已有简历 → Codex 读取该简历并提出修改 → 用户在平台查看差异，接受或拒绝；如其间已手动改动，旧建议不能覆盖最新内容。

## 6. 行为验收基线

以下是后续设计与测试应保护的用户行为，不表示已实现或已验证。

| 情境 | 预期结果 |
| --- | --- |
| 未连接 Codex | 仍可手动维护经历、创建与编辑简历、预览并导出 PDF |
| Codex 请求创建简历 | 只能读取该用户已确认的经历；提交独立草稿，不自动修改其他简历或经历库 |
| Codex 请求修改已有简历 | 仅能读取用户明确指定的简历；修改先展示待确认差异，拒绝不改变内容 |
| Codex 建议产生后用户手动修改简历 | 旧建议不能覆盖新版；需要基于最新内容重新提出 |
| JD 包含未经确认的能力或成果 | 不能当成用户事实写入简历；缺失的事实需要核实 |
| 用户修改一份简历或经历库 | 不自动同步到另一方或其他已生成简历 |
| 用户未提供 JD 或只提供岗位方向 | 可创建通用版；不能冒充某家公司定制版 |
