# Development Handoff

## Current work

- **Production cutover completed; one-time database reset removed.** The initial release backed up and rebuilt the application database and applied the API migration history successfully. Deployment now has one incremental migration path, with no database-action input or rebuild commands. It retains target validation, the deployment lock, readiness and Web/auth routing checks. Existing server backups are untouched. See [deployment documentation](deployment.md).
- **Design presets expanded.** The default template is named Onyx. Meowth adds uppercase accent-underlined section headings and inline work/education headers. Density offers Compact, Normal and Roomy, adjusting body line height, entry spacing and section spacing. Eight accent presets and manual six-digit HEX input are available. Incomplete color text stays local; valid colors autosave. Design groups use shadcn separators. Reset design removes saved design and typography overrides in one draft update, restoring Onyx, Classic 10 pt, Normal density and Blue. Optional per-resume design fields preserve defaults for older data. Selections autosave and apply to Forme and compatibility print output.
- **Default resume layout: aligned with the Onyx reference screenshot.** The document uses EB Garamond for headings and body, 14-point side margins, a blue contact rule and matching icons, right-aligned entry metadata, and a single-column skills list. The browser PDF renderer and compatibility print route share this layout. The EB Garamond faces load on demand from Google Fonts.
- **Preview and PDF rendering fixes:** the PDF.js compatibility build displays embedded fonts in Chromium versions without `Math.sumPrecise`. Contact icons are rasterized once per shape and style to preserve SVG geometry in Forme. List items use independent page boundaries to keep their markers with the corresponding text.
- **Design typography: implemented.** Write and Design swap the left editor panel while sharing the right preview. Design offers five font pairings and one Text size slider from 9 to 12.5 pt. The slider scales heading and body together. The preset and size autosave per resume. Existing per-field typography renders as saved until a preset is selected. The browser PDF and compatibility print use the same typography settings. The five presets share a versioned CDN font catalog between Forme and print CSS. Font downloads are cached during the editing session, and the Noto Sans SC fallback remains local.
- **Browser PDF font and rich-text compatibility: extended.** The Worker loads the bundled OFL-licensed [Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc) only for Han text and related punctuation. The asset is the pinned Google Fonts v40 regular face, compressed for transfer. Forme uses it per glyph after the selected PDF font. Markdown tables, horizontal rules and supported images now have native PDF output. The compatibility path still handles scripts outside available glyph coverage and images that the browser cannot fetch or decode.
- **Browser PDF generation: editor path implemented.** The editor converts the resume template to Forme document primitives. A browser Worker returns A4 PDF bytes and click-to-edit coordinates. The preview and download share the result, and the viewer draws visible pages only. Mobile Write mode pauses automatic PDF generation. An empty resume produces one A4 page. Hidden rich-text content stays out of the PDF, and the worker rejects text outside the page. On compatibility failure the eye button opens the Web print page directly. The download button can still call the Chromium renderer for unsupported markup, missing glyphs, or browser failures.
- **Preview navigation: implemented.** The right-hand document starts fitted to the available width in a native scroll area. Fit shows the whole first page and scrolls to the top. Wheel input scrolls vertically; dragging does not pan; the bottom minus/plus and Fit controls manage zoom, with the percentage visible. Only the “A4 · Live preview” caption is removed. Zoom changes reserve the correct scrollable document size without changing A4 layout or the chosen scale on resize. The user confirmed the normal login/resume-selection/editor flow works after correcting forwarding to another project's API; no port or environment changes were made during this UI slice.
- **Dependency readiness: implemented; isolated PostgreSQL integration verified.** [`HealthModule`](../apps/api/src/health/health.module.ts) keeps `GET /api/health` as lightweight liveness (`{ status: 'ok' }`) and now serves `GET /api/health/ready`. Readiness reuses [`DatabaseService.checkHealth()`](../apps/api/src/database/database.module.ts) to run `SELECT 1` with a 1-second deadline and attempts to cancel a timed-out query. It returns 200 with `status: ready / database: up`, or 503 with `status: not_ready / database: down`, without returning raw database errors. This checks basic query availability, not schemas, Google or PDF dependencies. No Redis dependency exists or was added. The old boolean application state/request gate remains removed; existing cache-header policy remains in place.
- **Common API Origin protection: implemented; isolated database integration verified.** [`originProtection`](../apps/api/src/common/middleware/origin.middleware.ts) is mounted once on `/api` in `main.ts`, after request logging/security headers and before native auth/body parsing. It allows GET/HEAD/OPTIONS without Origin and rejects every other method when Origin is missing or differs from the configured public origin, returning an empty, non-cacheable 403. Authentication and resource ownership remain with their existing owners. The duplicated auth/business Origin checks and business path list have been removed from startup; new API routes inherit the policy.
- **API initialization simplification: implemented; integrated regression checks passed.** [`main.ts`](../apps/api/src/main.ts) directly owns HTTP setup and the native Better Auth mount; the single-use HTTP/auth configuration helpers have been removed. It uses Pino in every environment and Nest's native SIGTERM/SIGINT hooks, with exit 0 after successful signal cleanup. Health endpoints belong to HealthModule as described above; `ApplicationState` and the readiness request gate remain removed. [`DatabaseService`](../apps/api/src/database/database.module.ts) releases connections in `onApplicationShutdown`, after HTTP draining. [`ShutdownDeadline`](../apps/api/src/lifecycle/shutdown-deadline.ts) bounds shutdown; `main.ts` retains minimal idle-socket cleanup after responses finish to avoid false shutdown timeouts. Request logging precedes rejections/parsing; native auth precedes Nest body parsers. Startup failure sanitization and cleanup remain.
- **Builder Basics follow-up: implemented, awaiting user acceptance.** Email/Phone share a row; Website/Location each have one row. Add field supports immediate focus, icon search, optional links, move-up and removal through the existing Zustand draft and shared `icon / label / link` contract.
- **Manual CRUD and shared resume contract: implemented; latest changes await normal-app acceptance.** API owns authentication, owner-scoped persistence and compatibility PDF rendering. Shared schemas and defaults live in `packages/contracts`. Typed sections, custom sections and ordering must survive save/reload alongside existing resumes.
- **Section pagination: implemented and accepted through automated checks.** All three tickets are done: [01: automatic pagination](plans/section-pagination/issues/01-automatic-pagination.md), [02: fresh-page starts](plans/section-pagination/issues/02-start-on-new-page.md), and [03: keep sections together](plans/section-pagination/issues/03-keep-section-together.md). The [spec](plans/section-pagination/spec.md) records section-menu rules and the rendering paths. A4 pages stack vertically, settings persist across save/reopen/reorder, hidden or empty sections add no breaks, and oversized content continues automatically.
- Remaining field parity, undo/redo, account-scoped draft recovery and other presentation controls are pending. The previous MCP server, provider / connection management, consent UI and local plugin package have been removed. MCP collaboration requires a new design; experience-library CRUD remains deferred.

## Blockers and risks

- The browser renderer embeds EB Garamond and uses Noto Sans SC when Han text is present. The compatibility path covers recognized missing glyphs and unsupported content. Measure client memory and responsiveness on representative devices and validate font coverage before retiring Chromium compatibility.
- The user authorized one temporary isolated-database test window for section pagination. Verification is complete and Resume Copilot's PostgreSQL container is stopped again; keep it stopped outside a further authorized development/test session. Do not use another project's services or data.
- `SHUTDOWN_TIMEOUT_MS` still defaults to 10 seconds; work exceeding that grace period, including a long PDF export, can be interrupted. Align the grace period with the eventual API deployment's termination deadline before claiming uninterrupted export during shutdown.
- Historical migrations 0002/0003, their snapshots and existing OAuth / connection tables remain in migration history. Their runtime schemas have been removed, so review any future generated migration for unintended table drops before applying it.
- Failed autosave drafts remain only in memory. Full-page unload warns about pending changes, but native browser-history navigation is not a reliable save barrier; recovery remains unfinished.
- The user changed server environment values after the successful release. Revalidate those values through a regular deployment and real Google account login. Follow the next master-branch deployment to verify reset removal.
