# Development Handoff

## Current work

- **Dependency readiness: implemented; live PostgreSQL verification deferred.** [`HealthModule`](../apps/api/src/health/health.module.ts) keeps `GET /api/health` as lightweight liveness (`{ status: 'ok' }`) and now serves `GET /api/health/ready`. Readiness reuses [`DatabaseService.checkHealth()`](../apps/api/src/database/database.module.ts) to run `SELECT 1` with a 1-second deadline and attempts to cancel a timed-out query. It returns 200 with `status: ready / database: up`, or 503 with `status: not_ready / database: down`, without returning raw database errors. This checks basic query availability, not schemas, Google or PDF dependencies. No Redis dependency exists or was added. The old boolean application state/request gate remains removed; existing cache-header policy remains in place.
- **Common API Origin protection: implemented; database integration deferred.** [`originProtection`](../apps/api/src/common/middleware/origin.middleware.ts) is mounted once on `/api` in `main.ts`, after request logging/security headers and before native auth/body parsing. It allows GET/HEAD/OPTIONS without Origin and rejects every other method when Origin is missing or differs from the configured public origin, returning an empty, non-cacheable 403. Authentication and resource ownership remain with their existing owners. The duplicated auth/business Origin checks and business path list have been removed from startup; new API routes inherit the policy.
- **API initialization simplification: implemented, integrated runtime recheck deferred.** [`main.ts`](../apps/api/src/main.ts) directly owns HTTP setup and the native Better Auth mount; the single-use HTTP/auth configuration helpers have been removed. It uses Pino in every environment and Nest's native SIGTERM/SIGINT hooks, with exit 0 after successful signal cleanup. Health endpoints belong to HealthModule as described above; `ApplicationState` and the readiness request gate remain removed. [`DatabaseService`](../apps/api/src/database/database.module.ts) releases connections in `onApplicationShutdown`, after HTTP draining. [`ShutdownDeadline`](../apps/api/src/lifecycle/shutdown-deadline.ts) bounds shutdown; `main.ts` retains minimal idle-socket cleanup after responses finish to avoid false shutdown timeouts. Request logging precedes rejections/parsing; native auth precedes Nest body parsers. Startup failure sanitization and cleanup remain.
- **Builder Basics follow-up: implemented, awaiting user acceptance.** Email/Phone share a row; Website/Location each have one row. Add field supports immediate focus, icon search, optional links, move-up and removal through the existing Zustand draft and shared `icon / label / link` contract.
- **Manual CRUD and shared resume contract: implemented; latest changes await normal-app acceptance.** API owns authentication, owner-scoped persistence and Chromium PDF rendering; Web shares its preview/print document with PDF export. Shared schemas and defaults live in `packages/contracts`. Typed sections, custom sections and ordering must survive save/reload alongside existing resumes.
- No further editor slice is selected. Remaining field parity, undo/redo, account-scoped draft recovery and presentation controls are pending. The previous MCP server, provider / connection management, consent UI and local plugin package have been removed. MCP collaboration requires a new design; experience-library CRUD remains deferred.

## Blockers and risks

- The user is working on other projects and intentionally leaves Resume Copilot's containers stopped. Keep them stopped; database-backed API regression checks are deferred until this project's local services are used again.
- `SHUTDOWN_TIMEOUT_MS` still defaults to 10 seconds; work exceeding that grace period, including a long PDF export, can be interrupted. Align the grace period with the eventual API deployment's termination deadline before claiming uninterrupted export during shutdown.
- Historical migrations 0002/0003, their snapshots and existing OAuth / connection tables are retained; no database migration or table drop was performed. Their runtime schemas have been removed, so review any future generated migration for unintended table drops before applying it.
- Failed autosave drafts remain only in memory. Full-page unload warns about pending changes, but native browser-history navigation is not a reliable save barrier; recovery remains unfinished.
- Production Compose has no NestJS service, and the deployment workflow still invokes the legacy Web migration command. API deployment, API-owned migrations, Chromium and API/Web reachability need a separate deployment slice. The Docker dependency-stage check does not validate the complete production image or deployment.
