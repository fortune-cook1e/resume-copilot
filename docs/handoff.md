## Blockers / Risks

- **Blocking provider race:** Better Auth OAuth Provider 1.7.5's `handleRefreshTokenGrant` calls `invalidateRefreshFamily(ctx, clientId, userId)` for a rotated token after the reuse window. That routine deletes refresh tokens by `(clientId, userId)`, spanning independent grants. Our supported before-hook intercepts ordinary replays, but the new scheduling test advances time between this hook and provider processing, causing the provider to invalidate the other connection. It also has an internal comment acknowledging the family invalidation is not transaction-safe. Do not patch package internals, hide this failing regression, or silently change providers. Provider 1.7.5 exposes no built-in refresh-replay override or hook enclosing its handler in the platform connection transaction; reviewed 1.7.6 retains the same behavior. A before-hook and wider retry window cannot guarantee isolation. The user accepted this known availability limitation **only for local normal-flow testing**; full A0/production still need an upstream fix or separately agreed architecture change. Revocation/refresh races and code replay remain unverified.
- MCP remains off by default in source configuration; the user-confirmed Codex plugin tool call does not establish ordinary Chat acceptance. User approved **deferring the known availability race for local normal-flow testing only**, not a production security waiver. Production migration and deployment remain unauthorized. Browser consent cancellation and desktop callback compatibility need real checks; management/revocation UI is not ready. Do not silently switch providers, register a second OAuth Provider, patch internals or weaken invariants.
- A Git marketplace alone distributes configuration, not an accessible server. Other users cannot connect to this machine's loopback MCP URL; external use requires a separately approved HTTPS deployment and the outstanding security fixes. Local Codex installation/authorization was user-confirmed, but ordinary Chat registration and authorization remain unverified. OpenAI's plugin auth guide advertises ChatGPT CIMD URLs at `/oauth/client.json` or `/oauth/{callback_id}/client.json`, unlike the current API allowlist for `/oauth/codex/...`; ordinary Chat may require a separately registered MCP app ID. Verify the actual host before changing auth, and never invent a registration ID.
- User's pre-upgrade Auth B acceptance must not be represented as current independent verification. Auth C still needs real two-tab/device behavior, failed sign-out/retry and browser Cookie renewal. Web Server Components and retained API handlers do not forward renewal Cookies from `/api/me`; native session-route renewal must be checked. Storage-unavailable fallback relies on Better Auth focus revalidation.
- `docker-compose.prod.yml` still runs only Web/PostgreSQL, not NestJS. Deployment requires a separately approved API service and trusted `API_INTERNAL_URL`; do not deploy it as-is.
- PDF export now requires Chrome/Chromium in the API runtime and API-to-Web reachability at `BETTER_AUTH_URL`. Migration does not remove per-export Chromium CPU/memory spikes on the same 2-core/2-GiB host; no worker or queue was added. The user chose to retain the current synchronous download experience.
- Existing API Vite/esbuild and Web Tiptap peer warnings remain. The user reports local acceptance of the editor/manual create/edit/PDF journey; production operation is unverified. Ollama polish is no longer in scope.
