- **Preview navigation: implemented.** The right-hand document is fixed and centered in a native scroll area. - **Dependency readiness: implemented; isolated PostgreSQL integration verified.** [`HealthModule`](../apps/api/src/health/health.module.ts) keeps `GET /api/health` as lightweight liveness (`{ status: 'ok' }`) and now serves `GET /api/health/ready`. Readiness reuses [`DatabaseService.checkHealth()`](../apps/api/src/database/database.module.ts) to run `SELECT 1` with a 1-second deadline and attempts to cancel a timed-out query. It returns 200 with `status: ready / database: up`, or 503 with `status: not_ready / database: down`, without returning raw database errors. This checks basic query availability, not schemas, Google or PDF dependencies. No Redis dependency exists or was added. The old boolean application state/request gate remains removed; existing cache-header policy remains in place.
- **Common API Origin protection: implemented; isolated database integration verified.** [`originProtection`](../apps/api/src/common/middleware/origin.middleware.ts) is mounted once on `/api` in `main.ts`, after request logging/security headers and before native auth/body parsing. It allows GET/HEAD/OPTIONS without Origin and rejects every other method when Origin is missing or differs from the configured public origin, returning an empty, non-cacheable 403. Authentication and resource ownership remain with their existing owners. The duplicated auth/business Origin checks and business path list have been removed from startup; new API routes inherit the policy.
- **API initialization simplification: implemented; integrated regression checks passed.** [`main.ts`](../apps/api/src/main.ts) directly owns HTTP setup and the native Better Auth mount; the single-use HTTP/auth configuration helpers have been removed. It uses Pino in every environment and Nest's native SIGTERM/SIGINT hooks, with exit 0 after successful signal cleanup. Health endpoints belong to HealthModule as described above; `ApplicationState` and the readiness request gate remain removed. [`DatabaseService`](../apps/api/src/database/database.module.ts) releases connections in `onApplicationShutdown`, after HTTP draining. [`ShutdownDeadline`](../apps/api/src/lifecycle/shutdown-deadline.ts) bounds shutdown; `main.ts` retains minimal idle-socket cleanup after responses finish to avoid false shutdown timeouts. Request logging precedes rejections/parsing; native auth precedes Nest body parsers. Startup failure sanitization and cleanup remain.
- **Builder Basics follow-up: implemented, awaiting user acceptance.** Email/Phone share a row; Website/Location each have one row. Add field supports immediate focus, icon search, optional links, move-up and removal through the existing Zustand draft and shared `icon / label / link` contract.
- **Manual CRUD and shared resume contract: implemented; latest changes await normal-app acceptance.** API owns authentication, owner-scoped persistence and Chromium PDF rendering; Web shares its preview/print document with PDF export. Shared schemas and defaults live in `packages/contracts`. Typed sections, custom sections and ordering must survive save/reload alongside existing resumes.
- **Section pagination: implemented and accepted through automated checks.** All three tickets are done: [01: automatic pagination](plans/section-pagination/issues/01-automatic-pagination.md), [02: fresh-page starts](plans/section-pagination/issues/02-start-on-new-page.md), and [03: keep sections together](plans/section-pagination/issues/03-keep-section-together.md). The [spec](plans/section-pagination/spec.md) records section-menu rules and the shared native browser pagination mechanism. A4 pages stack vertically; settings persist across save/reopen/reorder; hidden or empty sections add no breaks; oversized content continues automatically. Preview selection and the API print-readiness boundary are preserved. No subsequent editor feature is selected.
